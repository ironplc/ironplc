=====
P4043
=====

.. problem-summary:: P4043

This error occurs when a general (non-constant) expression is used as the
value in a structured or call-style initializer's ``name := value`` pairs
(e.g. ``tonDelta : TON := (PT := pDevice^.Delta);``) without the
``--allow-struct-initializer-expressions`` compiler flag.

The IEC 61131-3 standard grammar for a structured initializer value
(Annex B) is
``structure_element_initialization ::= structure_element_name ':=' (constant |
enumerated_value | array_initialization | structure_initialization)``. A
general expression -- and in particular a pointer dereference plus member
access like ``pDevice^.Delta`` -- is not one of those productions, so
accepting it is an extension used by TwinCAT and CODESYS, where such a
value is computed at instantiation time rather than being a compile-time
constant.

An ordinary constant, enumerated value, array initializer, or nested
structure initializer is standard syntax and is always allowed.

Example
-------

The following code will generate error P4043:

.. code-block::

   FUNCTION_BLOCK FB_Example
   VAR
       pDevice : REF_TO FB_Device;
       tonDelta : TON := (PT := pDevice^.Delta);
   END_VAR
   END_FUNCTION_BLOCK

``REF_TO`` is itself a dialect extension, so this example additionally needs
``--allow-ref-to`` (or a dialect that enables it, such as
``--dialect=codesys``). Under ``--dialect=twincat``, which does not enable
``REF_TO``, write the pointer as ``POINTER TO FB_Device`` instead.

To fix this error, use a constant value:

.. code-block::

   FUNCTION_BLOCK FB_Example
   VAR
       tonDelta : TON := (PT := T#100MS);
   END_VAR
   END_FUNCTION_BLOCK

Or enable the extension:

.. |flag| replace:: ``--allow-struct-initializer-expressions``
.. include:: /includes/enabled-by-flag.rst

What counts as a constant here
------------------------------

This error keys on the *shape* of the value, not on whether the value could
be computed at compile time. A single literal (``(x := 1)``, ``(x := -1)``)
is a ``constant`` in the standard grammar and is always accepted; an
arithmetic expression over literals (``(x := 1 + 1)``) is not, and produces
this error even though its result is fixed.

That is the difference from
:doc:`P4037 </reference/compiler/problems/P4037>` and
``--allow-constant-initializer-expressions``, which cover a plain ``VAR``
initializer and *do* fold the expression to a literal. A structured
initializer value is not folded, because the extension exists for values
that genuinely cannot be -- a pointer dereference read when the instance is
created. Write the computed value as a literal, or enable the flag above.
