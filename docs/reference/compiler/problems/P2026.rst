=====
P2026
=====

.. problem-summary:: P2026

This error occurs when a constant is not a value of the type it is used as.

Every integer type and every bit string holds a fixed range of values:

.. list-table:: Integer and bit string type ranges
   :header-rows: 1
   :stub-columns: 1

   * - Type
     - Minimum
     - Maximum
   * - **SINT**
     - -128
     - 127
   * - **INT**
     - -32768
     - 32767
   * - **DINT**
     - -2147483648
     - 2147483647
   * - **LINT**
     - -9223372036854775808
     - 9223372036854775807
   * - **USINT**, **BYTE**
     - 0
     - 255
   * - **UINT**, **WORD**
     - 0
     - 65535
   * - **UDINT**, **DWORD**
     - 0
     - 4294967295
   * - **ULINT**, **LWORD**
     - 0
     - 18446744073709551615

Storing a value outside that range would silently keep the low bits and
discard the rest, so ``c : SINT := 200`` would hold -56. Nothing in the
program says the value changes, so the compiler reports it instead.

Example
-------

The following code will generate error P2026:

.. playground::

   PROGRAM main
       VAR
           count : USINT := 300;  (* Error: a USINT holds 0 to 255 *)
           total : SINT;
       END_VAR

       total := 200;  (* Error: a SINT holds -128 to 127 *)
   END_PROGRAM

To fix this error, use a value the type can hold:

.. playground::

   PROGRAM main
       VAR
           count : USINT := 200;
       END_VAR
   END_PROGRAM

Or declare a type wide enough for the value you want:

.. playground::

   PROGRAM main
       VAR
           count : UINT := 300;
       END_VAR
   END_PROGRAM

Where the check applies
-----------------------

A constant is checked against the type it is used as, wherever it is used.
An untyped literal such as ``300`` takes its type from where it is used, so
the same literal can be a ``DINT`` in one place and a ``SINT`` in another.

An operand of an operator is used as the type the operator computes at,
because the operator does not widen the type. The same holds for an argument
of a standard function with a generic parameter, such as the ``ANY_NUM``
inputs of ``ADD``, for the bounds and step of a :code:`FOR` loop, and for the
count of a shift:

.. code-block::

   PROGRAM main
       VAR
           count : USINT;
           small : SINT;
           result : DINT;
       END_VAR

       count := 255 + 1;           (* Error: the sum is not a USINT *)
       small := ADD(small, 300);   (* Error: ADD computes at SINT here *)
       FOR small := 0 TO 300 DO    (* Error: the bounds are SINTs *)
           result := result + 1;
       END_FOR;
   END_PROGRAM

A comparison and a :code:`CASE` label are checked against the other operand
and the selector, where a constant the variable can never equal makes a
branch that can never run:

.. code-block::

   PROGRAM main
       VAR
           total : SINT;
           result : DINT;
       END_VAR

       IF total = 200 THEN  (* Error: a SINT is never 200 *)
           result := 1;
       END_IF;
   END_PROGRAM

A :code:`CASE` label is checked by its value whatever radix it is written in,
and so is each bound of a subrange label. ``16#FFFFFFFF`` is 4294967295, not
the -1 its bits would read as in a ``DINT``. A selector that is itself an
untyped literal has the type its value defaults to, ``DINT`` for an integer:

.. code-block::

   PROGRAM main
       VAR
           selector : DINT;
           small : SINT;
           result : DINT;
       END_VAR

       CASE selector OF
           16#FFFFFFFF: result := 1;  (* Error: a DINT is never 4294967295 *)
       END_CASE;
       CASE small OF
           100..300: result := 2;     (* Error: a SINT is never 300 *)
       END_CASE;
       CASE 5 OF
           4294967295: result := 3;   (* Error: the selector is a DINT *)
       END_CASE;
   END_PROGRAM

The same holds wherever a constant is stored: an element of an array
initializer (including each repetition, as in ``[2(300)]``), an element of a
structure or function block instance initializer, the default of a structure
field or a type declaration, a value written through a reference (``p^ := 300``
on a ``REF_TO SINT``), and an argument passed to a function or function block
input, which is checked against the parameter's type:

.. code-block::

   TYPE
       Small : USINT := 300;  (* Error: a USINT holds 0 to 255 *)
   END_TYPE

   FUNCTION Scale : USINT
       VAR_INPUT
           value : USINT;
       END_VAR
       Scale := value;
   END_FUNCTION

   PROGRAM main
       VAR
           readings : ARRAY[1..2] OF USINT := [1, 300];  (* Error *)
           result : USINT;
       END_VAR

       result := Scale(value := 300);  (* Error: the parameter is a USINT *)
   END_PROGRAM

A subrange type states its own range, and a constant outside it is reported
the same way:

.. code-block::

   TYPE
       Ratio : INT(0..10);
   END_TYPE

   PROGRAM main
       VAR
           r : Ratio := 20;  (* Error: Ratio holds 0 to 10 *)
       END_VAR
   END_PROGRAM

A prefixed literal states its own type
--------------------------------------

An integer literal can name its type with a prefix, as in ``INT#42``. The
prefix is a statement about the value, so the value is checked against the
prefixed type as well as against the type it is stored into. ``INT#40000`` is
not an ``INT``, whatever it is assigned to:

.. code-block::

   PROGRAM main
       VAR
           wide : DINT := INT#40000;  (* Error: an INT holds -32768 to 32767 *)
       END_VAR
   END_PROGRAM

To fix this error, name the type the value belongs to, or drop the prefix so
that the destination alone decides:

.. code-block::

   PROGRAM main
       VAR
           wide : DINT := DINT#40000;
           other : DINT := 40000;
       END_VAR
   END_PROGRAM

A literal that fits its own type but not the destination, such as
``small : SINT := INT#200``, is reported against the destination. A constant
is reported once, so one that fits neither is reported against its own type.

A radix form with a type prefix is checked by its value in the same way:
``INT#16#FFFF`` is 65535, which no ``INT`` can hold.

Bit strings
-----------

``BYTE``, ``WORD``, ``DWORD`` and ``LWORD`` hold the unsigned values of their
width, and a constant of one must be one of those values. ``BYTE#256`` is not
a byte, and neither is ``-1``:

.. code-block::

   PROGRAM main
       VAR
           mask : DWORD := -1;      (* Error: a DWORD holds 0 to 4294967295 *)
           pattern : BYTE;
       END_VAR

       pattern := BYTE#256;         (* Error: a BYTE holds 0 to 255 *)
   END_PROGRAM

To fill every bit, write the largest value, which is easiest to read in
hexadecimal: ``DWORD#16#FFFFFFFF``.

A value computed while the program runs still wraps at the width: with
``--allow-bit-string-arithmetic``, adding 1 to a ``BYTE`` that holds 255 gives
0. Only a constant is checked.

How a constant was written makes no difference to the check. ``16#1FF`` is
511 whichever radix it was spelled in, and a ``USINT`` cannot hold 511.
