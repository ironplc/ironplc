=====
P2026
=====

.. problem-summary:: P2026

This error occurs when a constant does not fit the type it is stored into.

Every integer type holds a fixed range of values:

.. list-table:: Integer type ranges
   :header-rows: 1
   :stub-columns: 1

   * - Type
     - Minimum
     - Maximum
   * - **SINT**
     - -128
     - 127
   * - **INT**
     - -32768
     - 32767
   * - **DINT**
     - -2147483648
     - 2147483647
   * - **LINT**
     - -9223372036854775808
     - 9223372036854775807
   * - **USINT**
     - 0
     - 255
   * - **UINT**
     - 0
     - 65535
   * - **UDINT**
     - 0
     - 4294967295
   * - **ULINT**
     - 0
     - 18446744073709551615

Storing a value outside that range would silently keep the low bits and
discard the rest, so ``c : SINT := 200`` would hold -56. Nothing in the
program says the value changes, so the compiler reports it instead.

Example
-------

The following code will generate error P2026:

.. code-block::

   PROGRAM main
       VAR
           count : USINT := 300;
           total : SINT;
       END_VAR

       total := 200;  (* Error: a SINT holds -128 to 127 *)
   END_PROGRAM

To fix this error, use a value the type can hold:

.. code-block::

   PROGRAM main
       VAR
           count : USINT := 200;
       END_VAR
   END_PROGRAM

Or declare a type wide enough for the value you want:

.. code-block::

   PROGRAM main
       VAR
           count : UINT := 300;
       END_VAR
   END_PROGRAM

Where the check applies
-----------------------

The type a value is stored or compared as bounds the constants written for
it. That includes an operand of an operator, because the operator does not
widen the type:

.. code-block::

   PROGRAM main
       VAR
           count : USINT;
       END_VAR

       count := 255 + 1;  (* Error: the sum is not a USINT *)
   END_PROGRAM

It also includes a comparison and a :code:`CASE` label, where a constant the
variable can never equal makes a branch that can never run:

.. code-block::

   PROGRAM main
       VAR
           total : SINT;
           result : DINT;
       END_VAR

       IF total = 200 THEN  (* Error: a SINT is never 200 *)
           result := 1;
       END_IF;
   END_PROGRAM

A subrange type states its own range, and a constant outside it is reported
the same way:

.. code-block::

   TYPE
       Ratio : INT(0..10);
   END_TYPE

   PROGRAM main
       VAR
           r : Ratio := 20;  (* Error: Ratio holds 0 to 10 *)
       END_VAR
   END_PROGRAM

A prefixed literal states its own type
--------------------------------------

An integer literal can name its type with a prefix, as in ``INT#42``. The
prefix is a statement about the value, so the value is checked against the
prefixed type as well as against the type it is stored into. ``INT#40000`` is
not an ``INT``, whatever it is assigned to:

.. code-block::

   PROGRAM main
       VAR
           wide : DINT := INT#40000;  (* Error: an INT holds -32768 to 32767 *)
       END_VAR
   END_PROGRAM

To fix this error, name the type the value belongs to, or drop the prefix so
that the destination alone decides:

.. code-block::

   PROGRAM main
       VAR
           wide : DINT := DINT#40000;
           other : DINT := 40000;
       END_VAR
   END_PROGRAM

The two checks are independent. A literal that fits its own type but not the
destination, such as ``small : SINT := INT#200``, is reported against the
destination only, and one that fits neither is reported once for each.

A radix form with an integer type prefix is checked by its value in the same
way: ``INT#16#FFFF`` is 65535, which no ``INT`` can hold. A bit pattern that
is meant to fill the word is spelled with a bit-string prefix, such as
``WORD#16#FFFF``, which is not checked.

A real constant stored into a REAL
----------------------------------

A real constant is an :doc:`/reference/language/data-types/elementary/lreal`
until it is stored. :doc:`/reference/language/data-types/elementary/real`
holds a smaller range, about -3.4028235E38 to 3.4028235E38, so a constant that
is a valid ``LREAL`` can still be too large for the ``REAL`` it is stored
into. Storing it would hold infinity in place of the number the program
wrote, so the compiler reports it instead. That includes a constant the
compiler computes from other constants:

.. playground::

   PROGRAM main
       VAR
           limit : REAL := 1.0E300;  (* Error: beyond REAL *)
       END_VAR

       limit := 1.0E30 * 1.0E30;  (* Error: 1.0E60 is beyond REAL *)
   END_PROGRAM

To fix this error, use a value a ``REAL`` can hold, or declare the variable as
``LREAL``:

.. playground::

   PROGRAM main
       VAR
           limit : LREAL := 1.0E300;
       END_VAR

       limit := 1.0E30 * 1.0E30;
   END_PROGRAM

A real literal that is too large for its own type, such as ``1.0E400`` or
``REAL#1.0E40``, is reported as :doc:`P2040` instead.

Bit strings are not checked
---------------------------

``BYTE``, ``WORD``, ``DWORD`` and ``LWORD`` hold bit patterns rather than
magnitudes, and wrapping one is a legitimate thing for a program to want. A
value too large for a bit string keeps its low bits without a diagnostic:

.. code-block::

   PROGRAM main
       VAR
           pattern : BYTE;
       END_VAR

       pattern := 255 + 1;  (* Accepted: a BYTE wraps to 0 *)
   END_PROGRAM

How a constant was written makes no difference to the check. ``16#1FF`` is
511 whichever radix it was spelled in, and a ``USINT`` cannot hold 511.
