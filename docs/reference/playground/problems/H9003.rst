=====
H9003
=====

.. problem-summary:: H9003

A request to advance the program by one or more scan cycles arrived after the
stepping session had already faulted, so execution could not continue.

When a program running in a stepping session hits a VM trap — a
:doc:`runtime problem </reference/runtime/problems/index>` such as division by
zero — the session is marked faulted and stops. A faulted session cannot be
resumed: its variable state reflects the moment of the fault, and continuing to
step would produce meaningless results. The session must be discarded with
``reset_session`` and rebuilt with ``load_program`` before stepping again.

When this happens
=================

This is an **internal error** that reflects a contract violation between the
playground front end and the WebAssembly module. After a fault the front end is
expected to surface the underlying trap and stop stepping until the user resets.
Seeing this code means a ``step`` call slipped through against an
already-faulted session, which indicates a bug in the playground's control flow.

How to fix it
=============

The real failure is the trap that faulted the session; look for the ``V####``
runtime problem reported alongside it and address that in your program. To clear
the faulted state, reload the page or reset and reload the program. If the code
appears without a preceding trap, please report it at
https://github.com/ironplc/ironplc/issues with the playground version shown in
the interface.
