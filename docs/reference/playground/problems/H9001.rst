=====
H9001
=====

.. problem-summary:: H9001

The playground compiled your program successfully but then failed to read back
the bytecode container it had just produced, so the stepping session could not
start.

This is an **internal error**. Unlike :doc:`H1002 <H1002>`, where the container
bytes come from outside and may legitimately be malformed, here the bytes were
generated moments earlier by the playground's own compiler. Failing to read them
means the freshly written container and the container reader disagree about the
format — which can only happen because of a bug in the compiler's container
writer or the runtime's container reader, not because of anything in your
program.

When this happens
=================

This error should never occur during normal use. If it does, it indicates a
defect in IronPLC: the container serialization and deserialization paths have
drifted out of sync, or the WebAssembly build bundled mismatched compiler and
runtime components.

How to fix it
=============

There is nothing to change in your IEC 61131-3 source — the program compiled
correctly. Please report this as a bug at
https://github.com/ironplc/ironplc/issues, including the program in the editor
and the playground version shown in the interface, so the maintainers can
reproduce it.
