=====
P2036
=====

.. problem-summary:: P2036

This error occurs when a TwinCAT ``REFERENCE TO`` is nested: a ``REFERENCE TO``
whose target is a reference or pointer type, or a reference of any kind whose
target is spelled ``REFERENCE TO``. TwinCAT declares neither ``REFERENCE TO
REFERENCE`` nor ``POINTER TO REFERENCE``. IronPLC gives a ``REFERENCE TO``
variable its automatic dereference by its own declaration, which a reference
reached through another reference does not have, and which does not reach
through a pointer the variable refers to, so a ``REFERENCE TO`` a pointer is
not supported either.

The IEC 61131-3 ``REF_TO`` and the CODESYS ``POINTER TO`` nest:
``REF_TO REF_TO INT`` and ``POINTER TO POINTER TO INT`` are references to a
reference, followed one level at a time with ``^``. See
:ref:`Nested references <ref-nested-references>` on the reference types page.

Example
-------

The following code will generate error P2036:

.. code-block::

   TYPE
       IntRef : REF_TO INT;
   END_TYPE

   PROGRAM Main
       VAR
           rr : REFERENCE TO IntRef;        (* Error: REFERENCE TO a reference *)
           pp : POINTER TO REFERENCE TO INT; (* Error: a reference to a REFERENCE TO *)
       END_VAR
   END_PROGRAM

To fix this error, refer to the reference with ``REF_TO`` or ``POINTER TO``,
which nest, or to the value itself with ``REFERENCE TO``:

.. code-block::

   TYPE
       IntRef : REF_TO INT;
   END_TYPE

   PROGRAM Main
       VAR
           x : INT;
           rr : REF_TO IntRef;       (* Correct: a reference to a reference *)
           r : REFERENCE TO INT;     (* Correct: a reference to a value *)
       END_VAR

       r REF= x;
   END_PROGRAM
